# Интернет-магазин спортивного питания

Веб-приложение для управления интернет-магазином спортивного питания, построенное на FastAPI с использованием SQLite в качестве базы данных.

## 🚀 Быстрый старт

### Запуск приложения

```bash
uvicorn main:app --reload
```

После запуска приложение будет доступно по адресу: `http://localhost:8000`

### 🔐 Тестовые учетные записи

Для тестирования функциональности администратора доступны следующие учетные записи:

**Учетная запись 1:**
- **Логин:** `admin`
- **Пароль:** `admin`

**Учетная запись 2:**
- **Логин:** `the_admin`
- **Пароль:** `the_admin`

### 🔐 Проверка администратора через sudo на Mac

При локальном запуске на macOS опасные действия в админ-панели требуют два подтверждения:
1. пользователь должен иметь роль `admin` в NutriSport;
2. текущий пользователь macOS должен подтвердить `sudo` в момент операции.

Например, при создании пользователя сервер сначала сбрасывает старый sudo-кэш командой `sudo -k`, затем запускает `sudo -v`. Если для `sudo` включен Touch ID, macOS сможет запросить отпечаток пальца. После успешного подтверждения выполняется сама операция, а затем сервер снова отзывает sudo-кэш командой `sudo -k`.

Приложение не принимает и не хранит пароль macOS. Открытие и просмотр `/admin` не требует `sudo`; проверка запускается только перед изменением данных. Если macOS не может показать Touch ID/пароль процессу сервера, операция должна завершиться ошибкой, а не выполниться без проверки.

Проверку можно отключить для разработки:

```bash
ADMIN_SUDO_VERIFICATION=0 uvicorn main:app --reload
```

### ✉️ Подтверждение заказа по почте

Перед оплатой заказа пользователь должен запросить одноразовый код на почту, указанную в профиле. Код действует 10 минут и привязан к текущему пользователю и выбранному адресу доставки. Без подтвержденного кода сервер не создаст платежную сессию и не оформит заказ.

Для отправки писем используются переменные окружения:

```bash
MAIL_LOGIN=...
MAIL_PASSWORD=...
MAIL_SMTP_HOST=smtp.mail.ru
MAIL_SMTP_PORT=465
```

## 🐳 Запуск в Docker

База SQLite лежит внутри контейнера в томе `nutrisport_data` (`/data/SportPit.db`).
При старте контейнера `seed_db.py` проверяет базу и, если в ней нет пользователей и товаров,
заполняет её из `db/seed.sql` (схема + тестовые данные, включая `admin` / `admin`).

```bash
cp .env.example .env        # при необходимости заполнить ключи Stripe и SMTP
docker compose up --build   # http://localhost:8000
```

Полезные команды:

```bash
docker compose exec web python seed_db.py --force   # досыпать seed поверх данных
docker compose down -v                              # удалить контейнер вместе с базой
```

Обновить `db/seed.sql` из локальной `SportPit.db` можно, переснимая дамп — seed-файл это обычный SQL.

## ☁️ Деплой на Render

1. Закоммитить и запушить `Dockerfile`, `render.yaml`, `seed_db.py`, `db/seed.sql`, `docker/`.
2. В Render: **New → Blueprint** → выбрать репозиторий. Render прочитает `render.yaml`.
3. Указать секреты `STRIPE_PUBLIC_KEY`, `STRIPE_SECRET_KEY`, `MAIL_LOGIN`, `MAIL_PASSWORD`.

На бесплатном плане диск эфемерный: база пересоздаётся из `db/seed.sql` при каждом деплое/рестарте.
Для постоянного хранения нужен платный план и блок `disk` в `render.yaml` (он там закомментирован).
